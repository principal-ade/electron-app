# Presence Connection Authentication Issue

## Summary
The Electron client successfully connects to the repository-traffic-controller WebSocket server and joins the `__global_presence__` room, but immediately receives an "Authentication required" error from the server. This prevents the presence system from working - no users appear in the online users list.

## Current Behavior

### Client Flow (Working ✅)
1. ✅ Client requests presence token from auth server (`/api/auth/cli/presence-token`)
2. ✅ Receives JWT with proper fields including `roomId: '__global_presence__'`
3. ✅ WebSocket connects successfully with `Authorization: Bearer <token>` header
4. ✅ Client calls `joinRoom('__global_presence__')`
5. ✅ Join succeeds - logs show "Subscribed to global presence"
6. ❌ **Immediately receives "Authentication required" error from server**
7. ❌ Client disconnects
8. ❌ User never appears in presence list (REST API returns `{ totalUsers: 0, users: [] }`)

### Client Logs
```
[GitSyncWebSocketManager] Presence token payload: {
  sub: 'SquallLeonhart13',
  userId: 'SquallLeonhart13',
  roomId: '__global_presence__',
  agentId: 'electron-de3e7d52-44f7-45ff-b6fa-cf92c470b224',
  permissions: [ 'presence:read', 'presence:write' ]
}
[GitSyncWebSocketManager] Calling joinRoom for __global_presence__...
[GitSyncWebSocketManager] Subscribed to global presence
[GitSyncWebSocketManager] Presence client error: Error: Authentication required
    at BaseClient.handleServerError (.../control-tower-core/dist/client/BaseClient.js:284:23)
```

## Expected Behavior

1. Client connects with JWT token
2. Client joins `__global_presence__` room
3. **Server fires `client:authenticated` event**
4. **Server calls `presenceManager.userOnline(userId, agentId)`**
5. User appears in presence list
6. Presence events broadcast to all connected clients

## The Problem

The server is sending an "Authentication required" error **after** the room join succeeds. This suggests:

1. **Possibility 1**: The server is trying to send another message (room state, event history, etc.) that requires additional authentication
2. **Possibility 2**: The `client:authenticated` event is never firing, so `userOnline()` is never called
3. **Possibility 3**: Some middleware or validation is rejecting subsequent messages after the initial join

## Technical Context

### Token Structure
The presence token is generated by `/api/auth/cli/presence-token` and includes:
```typescript
{
  userId: string;           // GitHub username
  roomId: "__global_presence__";  // Room authorization
  agentId: string;          // Device ID
  permissions: ["presence:read", "presence:write"];
  // ... standard JWT claims
}
```

### Server Architecture
From `server-control-tower.ts`, the expected flow is:

```typescript
// On client authentication (line 271-291)
server.on('client:authenticated', (data) => {
  const { clientId, userId } = data;
  const agentId = /* extracted from token */;

  // This should be called but ISN'T
  customPresence.mapClient(clientId, userId, agentId);
  customPresence.userOnline(userId, agentId, {}, true);
});
```

### REST API Mismatch
The REST endpoint `/api/presence/users` queries `presenceManager.getOnlineUsers()`, but since `userOnline()` is never called, the manager has no users registered, even though the WebSocket connection and room join succeed.

## Workaround Attempts

We've tried:
- ✅ Adding `roomId: '__global_presence__'` to the JWT token
- ✅ Ensuring token is sent in both WebSocket handshake AND `join_room` message payload
- ✅ Preventing duplicate `joinRoom()` calls
- ✅ Using Control Tower Core's `getCurrentToken()` mechanism
- ❌ Still getting authentication error after successful join

## Next Steps

This should be a simple flow:
1. Client connects → server authenticates from JWT header
2. Client joins `__global_presence__` → server authorizes from JWT `roomId` field
3. Server registers user in presence system
4. Done

But something in step 3 is failing. We need server-side logs to see what's happening between the successful room join and the authentication error.
