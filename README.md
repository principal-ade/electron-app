## Install

Clone the repo and install dependencies:

```bash
git clone --depth 1 --branch main https://github.com/electron-react-boilerplate/electron-react-boilerplate.git your-project-name
cd your-project-name
npm install
```

**Having issues installing? See our [debugging guide](https://github.com/electron-react-boilerplate/electron-react-boilerplate/issues/400)**

## Starting Development

Start the app in the `dev` environment (production-safe mode by default):

```bash
npm run dev
```

For development with unrestricted system access (not recommended):

```bash
npm run dev:unsafe
```

See [DEVELOPMENT.md](./DEVELOPMENT.md) for details on development modes.

## Packaging for Production

To package apps for the local platform:

```bash
npm run package
```

## Using the Shared Library

This app uses a local copy of the built shared library for slide rendering. To update the shared library:

1. Build the core library:
   ```bash
   cd ../core
   npm run build
   ```
3. Import components directly from `src/shared-lib`, for example:
   ```tsx
   import { SlideDeckRenderer } from '../../shared-lib/components/SlideDeckRenderer';
   ```

**Troubleshooting:**
- If you see module resolution errors, make sure you have copied the latest build.
- Re-run the copy script after any changes to the shared library.

## Testing

The project uses Jest for testing. There are three types of tests:

1. **Unit Tests**: Test individual components and utilities
2. **Integration Tests**: Test the interaction between components
3. **MCP Tests**: Test the Model Context Protocol integration

### Running Tests

To run all tests:
```bash
npm test
```

To run tests in watch mode (useful during development):
```bash
npm test -- --watch
```

To run specific test files:
```bash
npm test -- src/main/__tests__/mcp-server.test.ts
```

### MCP Testing Infrastructure

The MCP testing infrastructure includes:

1. **Mock MCP Server** (`src/main/__tests__/mcp-server.test.ts`):
   - Simulates MCP server behavior
   - Implements markdown verification
   - Handles mermaid diagram validation

2. **Test Utilities** (`src/main/__tests__/mcp-test-utils.ts`):
   - Helper methods for creating test content
   - Interfaces for message and response types
   - Utility methods for test creation

3. **Integration Tests** (`src/main/__tests__/mcp-integration.test.ts`):
   - Tests full Electron integration
   - Verifies IPC communication
   - Tests server lifecycle

Example test usage:
```typescript
import { MCPTestHelper } from './mcp-test-utils';

const helper = new MCPTestHelper();

// Test a single slide
const response = await helper.verifyMarkdown(
  helper.createTestSlide('# Test Slide')
);

// Test a presentation with diagrams
const presentation = helper.createTestPresentation([
  '# Slide 1',
  helper.createMermaidDiagram('graph', 'A-->B'),
  '# Slide 2',
  helper.createMermaidDiagram('sequence', 'A->>B: Hello')
]);

const response = await helper.verifyMarkdown(presentation);
```

### Test Coverage

All code changes should be covered by tests. The test suite includes:
- **Unit tests** for React components and utilities
- **Integration tests** for Electron main/renderer communication and MCP server lifecycle

Tests are run automatically in CI and can be run locally with:
```bash
npm test
```

### Pre-push Verification (Husky)

This project uses [Husky](https://typicode.github.io/husky/) to enforce code quality before pushing to the main branch.

- On `git push` to `main`, a pre-push hook will run `./verify-build.sh` to ensure all projects build and all tests pass.
- If any build or test fails, the push will be aborted.
- On other branches, the hook is skipped, but you can manually verify with:
  ```bash
  ./verify-build.sh
  ```
- To set up Husky hooks (if not already set up):
  ```bash
  npm install
  npm run husky install
  ./husky-setup.sh
  ```
- To skip the hook (not recommended):
  ```bash
  git push --no-verify
  ```

**Note:** See `HOOKS-README.md` for more details on hook setup and troubleshooting.
