# Store Normalized Events in Database

# Store Normalized Events in Database

## Problem
Currently, the observability SDK only stores raw hook logs (`pre_hook_logs`, `post_hook_logs`, `user_prompt_logs`) in Turso. The electron app normalizes events on-the-fly using `AgentEventPipeline` to create `RepoNormalizedUniversalAgentSessionEvent` objects for display.

However, external consumers (like the landing page) need to query these normalized events directly from the database without having to implement their own normalization pipeline.

## Current Flow
```
Agent Hook → HttpEventServer → AgentEventPipeline → RepoNormalizedEvent
                                                   ↓
                                            ObservabilitySDK (stores raw hooks only)
                                                   ↓
                                            Turso (pre_hook_logs, post_hook_logs, etc.)
```

## Desired Flow
```
Agent Hook → HttpEventServer → AgentEventPipeline → RepoNormalizedEvent
                                                   ↓
                                            ObservabilitySDK
                                                   ↓
                                    ┌───────────────┴───────────────┐
                                    ↓                               ↓
                            Raw Hook Tables              normalized_events table
                        (pre_hook_logs, etc.)         (with extracted file paths,
                                                       normalized paths, etc.)
```

## Requirements

1. **Create `normalized_events` table in Turso schema**
   - Include all fields from `RepoNormalizedUniversalAgentSessionEvent`
   - Key fields: `session_id`, `timestamp`, `event_type`, `file_paths` (JSON array), `repository_info`, `normalized_path_info`
   
2. **Update ObservabilitySDK to write normalized events**
   - When processing events through `AgentEventPipeline`, also write the normalized event to the new table
   - This should happen alongside writing to the raw hook tables
   
3. **Add query methods for normalized events**
   - `getNormalizedEventsForSession(sessionId)` - returns all normalized events for a session
   - Normalized events should include extracted file paths ready for map highlighting

## Benefits
- External apps (landing page) can query normalized events directly
- Consistent event structure across all consumers
- No need to duplicate normalization logic
- File paths already extracted and normalized for easy highlighting
