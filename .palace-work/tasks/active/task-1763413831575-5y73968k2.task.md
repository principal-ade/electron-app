# Task: Standardize Overlay Window Architecture

## Background
The electron app has two overlay windows (window switcher and quick open) that currently use different styling approaches:
- **Window Switcher**: Uses plain CSS (`window-switcher.css`)
- **Quick Open**: Uses ThemeProvider with theme object

Both windows share the same preload script (`src/window/preload.ts`) which exposes:
1. `window.mainProcess` - Full API suite (userPreferences, fileSystem, git, etc.)
2. `window.electronAPI` - Specific IPC methods for overlay windows (window list, selection, etc.)

## Questions to Answer
1. **Why does electronAPI exist separately from mainProcess?**
   - Is it for security/isolation?
   - Is it to minimize API surface for overlay windows?
   - Is it legacy architecture that should be unified?

2. **Should overlay windows use mainProcess APIs directly?**
   - Currently Quick Open uses both: `window.electronAPI` for IPC AND `window.mainProcess.userPreferences` for theme
   - Is this mixing of APIs intentional or should we standardize?

## Work Items

### 1. Document Current Architecture
- Map out all window types and their preload API usage
- Document what each API namespace is for
- Identify any security or architectural reasons for separation

### 2. Convert Window Switcher to ThemeProvider
**Current**: `src/renderer/window-switcher/`
- Uses plain CSS file: `window-switcher.css`
- No theme integration
- Hard-coded colors

**Target**: Match Quick Open pattern
- Add ThemeProvider wrapper
- Use theme object for colors: `theme.colors.background`, `theme.colors.text`, etc.
- Remove CSS file or convert to styled-components/inline styles with theme

**Files to modify**:
- `src/renderer/window-switcher/index.tsx` - Add ThemeProvider like quick-open
- `src/renderer/window-switcher/WindowSwitcherApp.tsx` - Use theme object
- `src/renderer/window-switcher/WindowCard.tsx` - Use theme colors
- Remove or refactor `src/renderer/window-switcher/window-switcher.css`

### 3. Standardize API Usage
Based on findings from #1, either:
- **Option A**: Keep separation, document why
- **Option B**: Consolidate to mainProcess only
- **Option C**: Create clearer boundaries (e.g., overlay windows only use electronAPI)

### 4. Testing
- Test Command+; (window switcher cycle mode)

- Test Command+O (quick open)
- Verify both overlays:
  - Display with correct theme colors
  - Respond to theme changes if applicable
  - Work in both light/dark modes
  - Handle keyboard navigation
